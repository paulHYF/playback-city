# 回放不夜城 · 开发计划

> 版本 v1.2 · 2026-10-23 · 范围：频道导入 → AI 生成 → 不夜城游戏 → 观众闯关数据 → 讲师助教大盘；v1.1 追加原始数据页与直播质量分析报告（M8）；v1.2 追加 AI 游戏配置的后台展示与调整（M9）；v1.2 观看记录拆分直播 / 回放与重点回顾段（M9）
> 已定（2026-10-23）：游戏页搬 v5 原型；讲次全部开放；直接在 master 开发。
> 需求真源仍是 `doc/需求文档.html`；本文只定**这一轮怎么做、按什么顺序做、做到什么算完**。

## 0. 现状盘点（2026-10-23）

| 部分 | 已有 | 缺口 |
|---|---|---|
| 后端取数 | `pipeline/fetch.py` 按 `channelId + fileId` 拉暂存、大纲、字幕、聊天、提问、观看、答题卡 → `data/<gid>/raw/` | 只能按单场拉，不能**按频道号一次导入**；没有频道信息、回放列表落库 |
| AI 生成 | `pipeline/analyze.py` + `schema.py` 生成并校验单场 `game.json`（rooms / items / world） | 没有**城级数据**（整座城的楼阁、街道、命名）；生成是同步请求，几分钟会超时 |
| 存储 | 文件：`data/<gid>/meta.json`、`game.json` | **没有数据库**；没有观众、闯关记录 |
| 前端后台 | `admin/` 游戏列表、频道暂存浏览、game.json 预览 | 没有「输入频道号导入」和**回放基础信息页** |
| 游戏 | `src/game/engine.ts` 只渲染地宫骨架；**完整玩法在 `prototype/v5-夜巡.html`**（地上广场 + 密室 + 道具链 + 众惑 + 店铺 + 昼夜），读 `v5-data.js`（由 `build_v5_data.py` 把 game.json + raw 打包） | 原型数据写死两场、讲次是假的；没接后端、没上报 |
| 讲师端 | 原型 v3 有「讲师视角」地面热力叠加 | 没有大盘页面 |

结论：**不重写玩法，把 v5 原型搬进前端工程，数据换成数据库驱动**；新增的是数据库、频道导入、城级生成、闯关上报、大盘五块。

## 1. 总体架构

```
            ┌──────────── 后台（/admin）────────────┐
 输入频道号 → 导入频道+回放列表 → 回放基础信息页 → 逐场「生成」→ 「生成整城」
            └───────────────────────────────────────┘
                              │ 后台任务（BackgroundTasks，状态写库，前端轮询）
                              ▼
 POLYV OpenAPI ──fetch──▶ data/<gid>/raw/*.json（原始数据缓存，保留文件）
                              │ analyze（大模型 + Pydantic 校验）
                              ▼
                    SQLite  backend/data/playback-city.db
     channel · replay(game_json) · city_json · viewer · play_run · play_event
                              │
        ┌─────────────────────┼──────────────────────────┐
        ▼                     ▼                          ▼
  观众端 /city/:cid      讲义 /handout/:rid        讲师助教 /dashboard/:cid
  地上广场 + 地宫闯关     （已有）                   立体点亮城 + 卡点分析
  首次进入发 viewerId
  闯关事件批量上报 ───────────────────────────────▶ 聚合
```

## 2. 数据库（最简：SQLite + 标准库 sqlite3）

- 文件：`backend/data/playback-city.db`（`backend/.gitignore` 已忽略 `data/*`，db 文件不进仓库）
- 不引 ORM：`app/db.py` 里一份 `SCHEMA` DDL，启动时 `CREATE TABLE IF NOT EXISTS`；JSON 字段用 TEXT 存（`game_json`、`city_json`、`extra`）
- 原始数据仍落文件（`raw/` 体积大、只给 analyze 用），**业务实体全部进库**
- 迁移：`uv run playback-city migrate` 把现有 `data/*/meta.json + game.json`（含 samples）导进库，现有三场真实数据不丢

| 表 | 主键 | 关键字段 | 说明 |
|---|---|---|---|
| `channel` | `channel_id` | name, publisher, cover_img, watch_url, scene(course/commerce), city_json, city_status, city_error, imported_at | 一个频道 = 一座城 |
| `replay` | `id`（= 暂存 fileId） | channel_id, video_id, title, duration_s, start_time, cover, url(m3u8), mp4, session_id, sort_no, subtitle_ready, game_status(none/fetching/analyzing/ready/failed), game_error, game_json, updated_at | 一讲回放 = 一座楼阁 / 一座地宫 |
| `viewer` | `id`（uuid） | nickname（自动起「夜巡人·xxxx」）, ua, first_seen, last_seen | 浏览器首次进入生成 |
| `play_run` | `id`（uuid） | viewer_id, replay_id, started_at, ended_at, result(cleared/dawn/escaped/abandoned), lamps_left, points, correct_cnt, wrong_cnt, revive_cnt, duration_s | 一局闯关 |
| `play_event` | 自增 | run_id, viewer_id, replay_id, type, room, ref, correct, choice, source_time, ts, extra | 闯关明细，大盘全靠它聚合 |
| `viewer_replay` | (viewer_id, replay_id) | best_result, cleared_at, best_points, tools | 观众在某讲的最好成绩；广场「挂朱旗」直接读它 |

`play_event.type` 枚举：`enter_palace` · `enter_room` · `answer`（ref=题 id，extra.kind=door/box/boss/rekindle）· `fall` · `revive_watch`（source_time + 看了几秒）· `npc_talk` · `tool_get` · `boss_win` · `clear` · `watch_replay`（广场绢幕/完整回放 from-to）

### 3.1.1 原始数据与质量报告（后台，2026-10-23 变更）

| 方法 | 路径 | 做什么 |
|---|---|---|
| GET | `/api/channels/{cid}/raw` | 原始数据总览：导入数据文件 + 每讲 raw 文件（名称、条数、大小、更新时间）+ 拉取失败原因 |
| GET | `/api/channels/{cid}/raw/import/{name}` | 读导入原始数据，`name` 白名单：`channel_info` · `playbacks` · `record_files` |
| GET | `/api/replays/{rid}/raw/{name}` | 读一讲的原始数据，`name` 白名单：`record_file` · `outline` · `subtitle` · `chat` · `questions` · `viewlog` · `viewlog_live` · `viewlog_vod` · `quiz` · `questionnaire` |
| POST | `/api/replays/{rid}/raw/refresh` | 只重拉这一讲的直播接口数据（不调模型、不重新生成密室），返回各文件是否拉到 |
| POST | `/api/viewers/{vid}/watch` | 回放城播放器上报真实播放区间 `{replayId, source: full\|clip, ranges: [[from,to]]}`，写 `replay_watch` 表；请求体按原文解析，兼容 `sendBeacon` |
| GET | `/api/channels/{cid}/report` | 直播质量分析报告：汇总、培训 / 营销两维度（指标、得分、诊断、建议）、逐讲明细、已生成的 AI 点评；每次请求按当前数据实时计算 |
| POST | `/api/channels/{cid}/report/ai` | AI 复盘点评（10.23 改版 v2）：**按频道场景只取主视角**（课程 → 教学效果漏斗，带货 → 营销转化漏斗），写给讲师 / 主播本人做复盘——一句话结论、总评、值得保持、问题诊断（证据 → 根因 → 影响，多信号交叉印证，单信号标「信号较弱」）、关键时刻复盘（第几讲 + 时间段 + 下次怎么讲）、按直播阶段的优化方案（优先级 + 验证指标）、开播前自检、复盘问题、数据缺口；Pydantic 校验不过回喂一次。存 `data/channels/<cid>/report_ai.json`，旧版或场景不符的点评不再展示，提示重新生成；模型不可用时返回 502 |

实现：`app/rawdata.py`（路径与白名单）、`app/report.py`（指标计算、打分、诊断、AI 点评）。打分口径见需求文档 F-14。

### 3.1.2 游戏配置展示与后台调整（2026-10-23 变更，M9）

AI 生成的两份配置都能在后台完整查看并人工调整，保存时过与 AI 生成**同一套 Pydantic 校验**，不通过逐条返回「字段路径：原因」；观众端 `/api/city/{cid}` 直接读库，重新进城即生效。

| 方法 | 路径 | 做什么 |
|---|---|---|
| PUT | `/api/replays/{rid}/game` | 保存调整后的单讲 game.json（殿室、题目、高频问题、易混、讲义、world 闯关配置）；`replay` 身份、`scene`、`skin` 以库里为准不可改；未生成或正在重新生成时 409 |
| GET | `/api/channels/{cid}/city` | 调整用的城数据：已对齐当前已生成的讲次（新讲次按兜底补楼并排到最后一条街，已不存在的讲次去掉）；还没生成整城时给兜底的一份当起点 |
| PUT | `/api/channels/{cid}/city` | 保存调整后的 city.json：每个已生成讲次恰好一座楼、恰好在一条街上 |

- 库：`replay.game_edited_at`、`channel.city_edited_at` 记录人工调整时间；重新生成写入新结果时清空。老库启动时自动 `ALTER TABLE` 补列
- 后台：`/admin/replays/:id` 由只读预览改为「游戏配置」页——殿室与题目 / 闯关配置 / 高频问题 / 易混概念 / 讲义 / JSON 六个页签，「调整配置」进入草稿编辑，保存或取消；JSON 页签兜底改表单没覆盖的字段。AI 没产出 world 时可「按殿室生成一份默认配置」再调
- 频道列表页（`/admin/channels`）操作列新增「游戏配置」下拉：整城配置（当前页弹窗）+ 已生成的各讲（进入单讲配置页）；没有已生成讲次时置灰
- 回放基础信息页：新增「楼阁」列与「调整整城配置」弹窗（表单 + JSON）；调整过的讲次 / 整城标「已调整」，点重新生成先确认会覆盖

观看分直播 / 回放（需求文档 F-15）：`fetch.py` 用 `GET /live/v2/statistics/{channelId}/viewlog` 按 `sessionIds` + `param3=live|vod` 拉逐次播放日志，接口不能跨月，按自然月切分（直播查开播当月，回放查开播起 12 个月）。报告里直播算在线曲线与流失点，回放算观众构成、补看、看回放时间；重点回顾段由 `play.review_ranges` 合并 `replay_watch`（播放器区间）与 `play_event` 的 `revive_watch`（复活片段），按 30 秒一格叠加。

## 4. AI 生成

### 4.1 单讲地宫 `game.json`（已有，改动小）
- 复用 `fetch` + `analyze`，入口从 `gid` 改成 `replay_id`，结果写库而不是写 `game.json` 文件（raw 继续写文件）
- 改成后台任务；失败把错误写 `game_error`，前端可「重新生成」

### 4.2 城级 `city.json`（新增）
大模型只负责**命名、分组、文案**；所有数值（楼高、亮灯、解锁）由程序按真实数据算。

```jsonc
{
  "name": "汴河夜市 · Python 入门",       // 城名
  "intro": "子时的汴河边，八座楼阁依次亮灯……",
  "streets": [{ "name": "容器街", "replays": ["<rid>", "<rid>"] }],  // 系列课一条街，按讲次排序
  "buildings": [{
    "replay": "<rid>",
    "name": "列表楼", "plaque": "容器为先",     // 楼名、匾额（≤6 字）
    "kind": "pavilion",                       // 枚举：pavilion 楼阁 / hall 殿 / shop 店铺 / tower 塔
    "blurb": "这一讲讲列表、字典与循环"
  }],
  "npcs": [{ "replay": "<rid>", "name": "更夫老周", "line": "第三讲门口卡住的人最多……" }]
}
```

- 输入：频道信息 + 每讲的标题 / 时长 / rooms 标题与摘要 / 高频 faq（已生成的 game.json 摘一份）
- 校验（Pydantic `City`）：每个 ready 的 replay 恰好出现一次；kind 只能取枚举；校验失败回喂一次，再失败用程序兜底（按讲次一条街，楼名=标题前 6 字）
- 程序计算：楼层数 = 观看量分档（回放列表无观看量时用观看记录人数）
- 解锁：**已生成的讲次全部开放**（2026-10-23 定），没生成的显示「未开」

### 5.2 讲师助教大盘：立体点亮城
沿用构思记录 18.2 的「GitHub Skyline」思路 + 设计稿 v2 的「遗忘变暗」，复用 v5 广场的楼阁建模，换成俯视轨道相机：

| 视觉 | 对应数据 |
|---|---|
| 楼高（层数） | 这一讲进入闯关的观众数 |
| 亮窗比例 | 通关率：每有一位观众通关，点亮一扇窗 |
| 楼身色温（冷青 → 灯火橙 → 朱红） | 全讲平均错误率 |
| 楼顶朱红信标 | 卡点最重的殿室错误率 > 50% |
| 街道灯笼 | 复活回看次数（大家在补看哪一讲） |
| 时间轴回放 | 拖动 / 播放：按 `clear` 事件时间逐窗点亮，看「城是怎么被点亮的」 |

点一座楼 → 右侧面板展开单讲：地宫平面（殿室按错误率染色 + 百分比，同原型 v3 讲师视角）、殿室漏斗、错题榜（含学员最常选的错误选项 = 混淆点）、复活回看热度带（叠在回放进度条上，点击跳回放）、观众列表。

### 5.4 闯关配置全部接入引擎（2026-10-23 变更，M11）

此前引擎只读了 `world.clock`，殿室机制、门题、道具链、布局、氛围、地名、NPC 台词都没生效（后台「P1/P2 降级」提示不实）。现在全部接入，与主题无关、所有主题通用：

| 配置 | 引擎表现 |
|---|---|
| `rooms[].mechanic` | `chest_quiz` 卷宗匣（依次答本房题，排除门题那道）· `twin_doors` 石碑辨析 + 两扇刻字门 · `order_steps` 机关台按序点步骤（错两次反噬）· `code_fill` 符文碑选填法 · `calc` 账台输入答案（数字按值比、可错一次）；引擎内置玩法也可指定：`lamps` 拾灯 · `evidence` 寻证 · `sort` 找同类 · `assemble` 拼原话 · `beasts` 破惑。Boss 殿固定 Boss 对决；未配置殿室按默认轮换 |
| `rooms[].door` / `reward` | 本殿出口门挂门题，答对才开，开门得 `reward` 道具；门题先于道具检查 |
| `rooms[].requires` + `items` | 配了 `items` 即启用自定义道具链：进门要持有指定道具，内置灯油 / 铜鱼符链停用 |
| `rooms[].layout` | `corridor` 窄长 10×5 · `courtyard` 10×8 不封顶 · `stall_row` 10×6 摆件更多 · `hall` 默认 |
| `rooms[].mood` | `dim` 不挂灯 · `misty` 低处雾团 · `lit` 默认 |
| `rooms[].name` / `world.name` / `intro` | 殿室地名、地宫名、进地宫旁白 |
| `npcs` | 指定殿室、答哪条高频问题、开场台词 |
| `boss.reward` | 胜利掉落道具 |

答错都按原规则：灭一盏灯并看完对应回放；埋点 `answer.extra.kind` 为机制名，门题为 `door`。左侧「本室任务」面板覆盖全部机制与门题。
